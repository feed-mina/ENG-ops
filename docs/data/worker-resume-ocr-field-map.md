# 구직표·이력서 OCR 검토 필드와 근로자 접수 매핑

> 기준일: 2026-07-27. 실제 첨부 이미지나 OCR 원문은 저장소·GitHub·Mock fixture에 넣지 않는다. 이 문서는 문서에서 관찰되는 **필드 유형**만 다루며 예시는 모두 합성 값이다.

## 현재 구현 경계

- `public/`의 근로자 화면은 가명·마스킹된 합성 근로자 **목록 화면**이며 등록 폼이 아니다.
- 실제 입력 계약은 `packages/contracts/operations.js`의 `normalizeWorkerIntake()`이다.
- OCR 검토 계약은 `packages/contracts/worker-resume.js`이며 원문·이미지를 저장하거나 근로자 접수를 자동 생성하지 않는다.
- 합성 예시는 `mock-documents/mock-worker-resume-ocr-review.json`만 사용한다.

## 문서 필드 구조

| 문서 필드 유형 | OCR 처리 | 구조화 후보 | 근로자 접수 반영 |
|---|---|---|---|
| 증명사진 | 이미지 입력 차단 | 없음 | 반영하지 않음 |
| 성명·서명 | 즉시 마스킹 | 합성 `displayAlias`만 허용 | 본인 동의 후 운영자가 별칭 확인 |
| 주민등록번호·신분증 번호 | 즉시 마스킹하고 문서 반입 차단 | 없음 | 수집 금지 |
| 생년월일 | 즉시 마스킹 | 없음 | 동의 후 `birthDate`를 별도 확인 입력 |
| 전화번호·이메일 | 즉시 마스킹 | `contactMask` | 원문을 복사하지 않고 동의 후 연락처 재입력 |
| 상세주소 | 즉시 마스킹 | 없음 | 상세주소는 수집하지 않고 `preferredAreas`만 별도 확인 |
| 학력 | 검토 후보 | `educationSummary` | 현재 계약에서 수집하지 않음 |
| 경력 | 검토 후보 | `experienceSummary`, `workHistory` | 운영자 확인 후 `experience`에 최소 요약 병합 |
| 자격·교육 | 검토 후보 | `qualifications` | 업무 관련 항목만 확인 후 `experience`에 최소 요약 병합 |
| 수상·표창 | 검토 후보 | `awardSummary` | 현재 계약에서 수집하지 않음 |
| 계좌·카드·인증정보 | 즉시 마스킹하고 문서 반입 차단 | 없음 | 수집 금지 |
| 건강진단 상세·질병명 | 즉시 마스킹하고 문서 반입 차단 | 없음 | 상세결과 대신 보건증 확인 상태·확인일·만료일만 별도 입력 |

## 현재 근로자 화면·계약과 비교

| 영역 | `public/` 목록 표시 | `normalizeWorkerIntake()` 입력 | OCR 직접 반영 |
|---|---|---|---|
| 식별 | 가명, Mock ID | Mock ID, 별칭 | 별칭 후보만 사람 확인 |
| 연락 | 마스킹 전화 | Mock 전화번호 | 불가 · 동의 후 재입력 |
| 기본 조건 | 직종, 선호지역, 가능일, 희망임금 | 직종, 가능일·시간, 선호지역, 경험, 희망임금 | 경력·직종 후보만 사람 확인 |
| 자격 상태 | 보건증 상태·만료일 | 보건증 상태·확인일·만료일, 체류자격 | OCR 건강 상세는 반영 금지 |
| 동의 | 동의 상태 표시 | 목적별 동의 필수 | OCR로 추정하지 않음 |
| 선택정보 | 회원형태 | 이동수단, 긴급연락처, 운영자 메모 | 이력서에서 자동 복사하지 않음 |

## 처리 순서

1. OCR 텍스트는 메모리에서 `analyzeWorkerResumeOcrText()`로 즉시 마스킹한다.
2. 차단 정보가 발견되면 문서 반입을 중단하고 원문·이미지를 폐기한다.
3. 마스킹 결과는 저장하지 않고 운영자가 화면에서만 필드 후보를 검토한다.
4. 필요한 업무 정보만 합성 fixture 구조처럼 정리한다.
5. 실제 운영에서는 목적별 동의를 받은 뒤 현재 근로자 접수표에 다시 입력한다.
6. OCR 결과만으로 등록·매칭·배정·거절을 수행하지 않는다.
