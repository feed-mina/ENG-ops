## 3. 대표 업무 흐름 Mock

### 하루 근무

식당 구인 접수 → 사업자·근로조건 확인 → 후보 검색 → 양측 전화 확인 → 식당·근로자 계약 → 식당 직접 임금 지급 → 소개결과·요금 기록

### 1개월 근무

기간·월임금·지급일 접수 → 사업자·최저임금 확인 → 장기근무 후보 검색 → 양측 조건 확인 → 근로계약서 작성 → 식당 근태·임금 관리 → 취업·요금·변경사항 기록

### 회원제 일용근로자

회원 조건 등록 → 회원 약정·회비 확인 → 식당 요청 대조 → 양측 전화 확인 → 하루 근로계약 → 식당 직접 임금 지급 → 회원명부·소개기록·회비 기록

## 4. 역할 경계

| 식당 | 직업소개소 |
|---|---|
| 근로계약 체결 | 구인·구직 조건 접수 |
| 현장 업무 지휘·안전 안내 | 사업자·근로조건 검증 |
| 근로시간 확인 | 후보 연락과 양측 조건 확인 |
| 임금 계산·직접 지급 | 소개·취업·요금 장부 기록 |

소개소가 근로자를 직접 지휘하거나 식당 대신 임금을 지급하는 흐름은 Mock에서도 허용하지 않는다.

## 5. 실제 현장에서 확인할 질문

1. 실제 운영시간과 정기 휴무일은 무엇인가?
2. 대표자 외 종사자가 있는가? 최근 교육 수료일은 언제인가?
3. 보증보험의 실제 증권번호·가입금액·만료일은 무엇인가?
4. 하루 근무와 월 근무의 임금 지급일·방법을 어떻게 확인하는가?
5. 결근·조기퇴근·대체인력·사고·분쟁을 어떤 수첩이나 서식에 기록하는가?
6. 현재 수첩과 서식에 법정 장부 필수항목이 모두 있는가?

## 6. 실제 자료로 교체하는 방법

1. 원본은 GitHub에 올리지 않는다.
2. 사장님이 원본을 보면서 항목별 사실만 확인한다.
3. 확인일·확인자·원본 종류를 별도 검증 기록에 남긴다.
4. 필요한 샘플은 이름·번호·계좌·서명을 완전히 가린 사본만 사용한다.
5. Mock 값은 바로 덮어쓰지 않고 `mock → 확인 대기 → 원본 확인` 상태로 변경한다.
