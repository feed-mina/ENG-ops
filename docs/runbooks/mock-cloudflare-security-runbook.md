# Cloudflare 보안 전환·복구 Mock 실행서

> 실제 계정 설정이나 개인정보 사고 기록이 아닌 훈련용 문서입니다. 담당자와 날짜는 모두 가상 값으로만 기록합니다.

## 1. Access 출시 점검

1. 내부 Worker와 미리보기 주소를 각각 Access self-hosted application으로 등록한다.
2. 기본 거부를 확인한 뒤 대표자와 승인 종사자 그룹만 Allow 정책에 넣는다.
3. IdP에서 MFA를 요구하고 세션 만료시간을 정한다.
4. 허용되지 않은 계정, MFA 미완료 계정, 퇴사 처리 계정으로 차단 테스트를 한다.
5. Worker의 `ACCESS_TEAM_DOMAIN`, `ACCESS_AUD`를 환경별 일반 변수로 넣는다.
6. Access 통과 후에도 앱 역할에 따라 내보내기와 파기가 차단되는지 확인한다.

## 2. 키 생성과 교체

1. PII AES 키와 감사 HMAC 키를 서로 다른 32바이트 이상 난수로 만든다.
2. 키 값은 비밀번호 관리자에서 승인된 담당자만 보관하고 Workers Secrets로 입력한다.
3. 키 식별자는 비밀이 아니지만 변경 이력을 남긴다.
4. 교체 작업은 Mock 복제본에서 복호화 → 새 키 암호화 → 건수 검증을 먼저 수행한다.
5. 운영 교체 후 이전 키는 정해진 유예기간 뒤 삭제하고 복구 가능 여부를 확인한다.

## 3. 백업과 복구 훈련

목표 초안은 RPO 24시간, RTO 4시간이다. 실제 D1 요금제와 Time Travel 보존기간을 확인한 뒤 확정한다.

1. 복구 직전 장부 건수, 소개요금 건수와 합계, 최신 감사 해시를 기록한다.
2. 운영 DB를 직접 덮지 않고 별도 복구 DB에 지정 시점으로 복원한다.
3. 마이그레이션 버전과 주요 테이블 건수를 비교한다.
4. 소개요금 합계와 감사 해시 연결을 검증한다.
5. 권한 있는 시험 계정으로 최소 조회를 확인한다.
6. RPO/RTO 결과와 불일치를 기록한 뒤 복구 DB를 파기한다.

Time Travel 명령과 보존범위는 실행 당일 Cloudflare 공식 문서를 다시 확인한다. 이 저장소에는 운영 백업이나 데이터 내보내기를 커밋하지 않는다.

## 4. 계정탈취·기기분실 대응

1. Access/IdP 계정을 즉시 중지하고 활성 세션을 무효화한다.
2. D1 `app_principals.active`를 0으로 바꾸고 회수 시각을 기록한다.
3. 감사로그에서 해당 내부 사용자 ID의 조회·내보내기·권한변경을 확인한다.
4. 유출 범위를 추정하되 실제 개인정보를 이슈나 메신저에 붙이지 않는다.
5. 필요한 신고·통지 여부는 개인정보 보호 책임자와 관계기관 기준으로 판단한다.
6. 기기 초기화, 암호 교체, 재발방지 교육 후 새 계정으로 재승인한다.

## 5. 온라인 접수 활성화

현재 `INTAKE_ENABLED=false`다. 다음을 모두 확인하기 전에는 바꾸지 않는다.

- 공개 폼의 목적별 동의문 확정
- Turnstile 사이트키와 비밀키의 환경 분리
- Siteverify 서버 검증, hostname/action 확인, 토큰 재사용 차단
- 요청 크기·허용 필드·민감정보 패턴 차단
- 공개 코드에 D1 읽기 경로가 없음을 테스트
- 접수 실패 때 전화 안내만 하고 본문을 로그에 남기지 않음
