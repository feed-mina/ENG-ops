# 개인정보 문서 묶음 — Mock 초안

> 실제 근로자나 식당에 서명받는 문서가 아닙니다. 운영 전 수집 목적, 법적 보존기간, 제공 대상, 담당자 연락처를 현장·법률 검토로 확정해야 합니다.

## 개인정보 처리방침 초안 항목

- 처리 목적: 구직 상담, 구인 조건 확인, 직업소개, 소개 결과와 법정 장부 관리
- 필수 항목과 선택 항목의 분리
- 식당에 제공하는 최소 항목과 제공 시점
- 항목별 보존 시작점·기간·파기방법
- 처리 위탁과 국외 이전 여부
- 열람·정정·삭제·동의철회 요청 방법
- 개인정보 보호 담당자와 사고 문의 경로

## 근로자 수집·이용 동의 Mock

필수 항목은 가상 이름, 가상 연락처, 희망직종, 근무 가능 날짜·시간·지역, 희망임금이다. 보건증은 확인 상태와 만료일만 기록한다. 실제 운영에서도 주민등록번호, 신분증 원본, 건강진단 상세결과는 기본 수집 항목으로 두지 않는다.

## 식당 제공 동의 Mock

특정 식당과 근로조건을 먼저 알려준 뒤 소개에 필요한 최소 정보만 제공한다. 공개 근로자 명단은 만들지 않는다. 제공 대상 식당, 제공 항목, 목적, 제공 시각, 동의 버전을 별도 기록한다.

## 선택정보 동의 Mock

이동수단과 긴급연락처는 선택정보로 분리한다. 동의하지 않아도 기본 상담을 거절하지 않는다. 선택정보가 실제 배정에 불필요하면 수집하지 않는다.

## 내부 개인정보 취급 수칙 Mock

- 공용계정을 사용하지 않고 화면 잠금과 기기 암호화를 켠다.
- GitHub 이슈, 일반 메신저, 개인 클라우드에 실제 개인정보를 올리지 않는다.
- 업무상 필요한 레코드만 열고 대량 조회·내보내기는 대표자 승인을 받는다.
- 출력물은 잠금 보관하고 만료 시 분쇄한다.
- 오발송·분실·의심 접근은 숨기지 말고 즉시 대표자에게 알린다.

## 접근권한 신청·변경·회수 Mock

신청자 내부 ID, 요청 역할, 필요 업무, 승인자, 시작일, 재검토일, 회수일을 기록한다. 권한 변경 이유에 실제 개인정보를 적지 않는다.

## 위탁·외부 AI 점검 Mock

- 처리업체와 데이터 위치
- 학습 사용 여부와 거부 설정
- 전달 필드 최소화·가명화
- 재위탁, 보존기간, 삭제 확인
- 침해사고 통지와 감사 권리

이 조건을 확인할 수 없는 외부 AI에는 근로자·식당 원문을 전달하지 않는다.
