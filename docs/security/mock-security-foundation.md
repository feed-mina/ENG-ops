# #9·#15 Mock 보안 기반 설계

> 이 문서는 가상 계정과 가상 자료로 보안 흐름을 검증하기 위한 초안입니다. 실제 개인정보 처리방침, 동의서, Access 계정 또는 복구 증빙이 아닙니다.

## 시스템 경계

| 구분 | 공개 홍보 사이트 | 내부 업무 Worker |
|---|---|---|
| 배포 단위 | `apps/public-site` / Cloudflare Pages | `apps/ops-app` / Cloudflare Worker |
| 데이터 조회 | 없음 | Access와 앱 권한을 통과한 경우만 |
| D1 바인딩 | 없음 | `DB` 바인딩 소유 |
| 온라인 접수 | 현재 없음 | 쓰기 전용 진입점도 아직 비활성 |
| 개인정보 | 받거나 저장하지 않음 | 현재는 Mock 형식만 허용 |

공개 페이지에서 내부 Worker 주소를 링크하지 않는다. 주소를 아는 것만으로는 접근할 수 없으며 Cloudflare Access 정책, Worker의 JWT 재검증, D1 역할권한을 모두 통과해야 한다.

## 인증과 MFA

로그인 화면과 MFA는 애플리케이션이 직접 만들지 않고 Cloudflare Access와 연결한 IdP에서 담당한다. Worker는 `Cf-Access-Jwt-Assertion`을 받아 다음을 다시 확인한다.

1. RS256 서명과 `kid`가 Access 공개키와 일치하는지
2. 발급자(`iss`)가 지정한 Access 팀 도메인인지
3. 대상(`aud`)이 내부 애플리케이션 AUD인지
4. 만료(`exp`)와 사용 시작(`nbf`) 시간이 유효한지
5. `sub`가 D1의 활성 내부 사용자로 등록되어 있는지

토큰 헤더의 이메일이나 사용자가 보낸 임의 헤더는 권한 판단에 사용하지 않는다. 실제 MFA 정책과 세션 시간은 Cloudflare Access 설정 후 별도로 화면 캡처와 테스트 기록을 남긴다.

권한은 `apps/ops-app/src/rbac.js` 한 곳에서 정의한다. 퇴사·업무변경 때 `active=0`과 회수시각을 기록하고, Mock 정책은 분기마다 재검토하도록 설정했다.

## 암호화와 키 분리

- 전화번호 등 중요 필드는 AES-256-GCM으로 암호화한다.
- 레코드와 필드명을 추가 인증 데이터로 묶어 암호문을 다른 필드에 옮겨 쓸 수 없게 한다.
- 암호문에는 키 값이 아니라 키 식별자만 기록한다.
- `PII_ENCRYPTION_KEY`, `AUDIT_HMAC_KEY`는 Workers Secrets로만 넣고 Git에 커밋하지 않는다.
- 키 교체 전 기존 키로 복호화하고 새 키로 다시 암호화하는 별도 승인 작업을 수행한다.

Cloudflare의 저장 암호화만으로 앱 수준의 최소노출 요구를 대신하지 않는다. 반대로 앱 필드 암호화만으로 D1·기기·백업 통제를 대신하지 않는다.

## 감사와 이상징후

감사 상세에는 요청번호, 내부 레코드 번호, 결과코드, 변경 필드명, 건수만 허용한다. 성명, 전화번호, 주소, 건강정보, 요청 본문은 버린다. 이벤트는 앞 이벤트 해시와 HMAC으로 연결하며 D1 트리거가 UPDATE와 DELETE를 거부한다.

운영 단계에서 별도 알림으로 연결할 조건은 다음과 같다.

- 10분 동안 반복된 Access 실패
- 업무시간 밖의 상세조회
- 한 요청에서 50건 이상 조회
- 모든 내보내기, 권한변경, 파기
- 감사 해시 연결 불일치

## 보존과 파기

`statutory-ledger-2y`와 `general-operational`을 분리한다. 만료일이 지났더라도 `legal_hold=1`이면 자동 후보에서 제외한다. 파기는 대표자 권한으로 실행하고 대상, 방식, 실행자, 검증자, 시각을 `destruction_evidence`에 남긴다.

현재 `cryptographic-erasure-mock`은 검증용 상태명이다. 운영 파기에서는 D1 원본, 내보낸 파일, 종이, 휴대전화, PC, Time Travel 가능 기간을 포함해 단계별 완료를 확인해야 한다.

## 출시 전 남은 게이트

- 실제 Access 애플리케이션과 기본 거부 정책 생성
- 대표자·승인 종사자 IdP 등록 및 MFA 실증
- 운영/미리보기 D1 분리 생성과 마이그레이션 적용
- Workers Secrets 등록과 키 교체 훈련
- D1 Time Travel 또는 승인된 내보내기를 사용한 복구 훈련
- 개인정보 처리방침·목적별 동의문 법률/현장 확인
- Turnstile 위젯·비밀키 생성과 서버 검증 후 온라인 접수 활성화
